# Logical computer checkpoints

The Rust checkpoint API and C ABI 21 expose bounded logical capture and restoration through both JNI and FFM. World-store methods provide atomic publication and consumption; host integrations own freeze, world-action settlement, resource rebinding and activation.

Rust owns the logical execution payload. It stores verified executable bytes for the root and every live child, execution profiles and process limits, admitted capability identities, machine and session state, terminal and canonical input, redstone waits, exact `/home` namespace generation and immutable file bytes, and open handle generations. Admission rebuilds execution images from verified artifacts and checks state against those images and trusted host configuration. Rust layouts, addresses, allocation capacities, and process-local machine identity are not persisted.

The execution envelope has a fixed 84-byte little-endian header: `CPKTHIB\0` (8 bytes), format version (u32, currently 2), runtime/schema identity (SHA-256, 32 bytes), computer ID (16 bytes), filesystem generation (u64), execution length (u64), and host descriptor length (u64). Execution and opaque host descriptor bytes follow, then SHA-256 over the complete header and both payloads. Runtime identity hashes the schema identity, a zero byte, and the native C ABI as a little-endian u32. The ABI comes from the canonical Runtime minor component; `cargo xtask check` verifies agreement with the exported FFI ABI. Package revisions do not participate in identity. The earlier development identity based on the full package version is rejected; no legacy fallback is admitted. Any incompatible constituent codec or meaning change requires an ABI increment and an appropriate format/schema version change before persisted admission is exposed. A revision must preserve checkpoint compatibility in both directions.

Readers reject unsupported identity/version, another computer ID, checksum failure, truncation, trailing bytes, inconsistent filesystem generation, oversized payloads, and allocation budget exhaustion. The execution decoder also applies depth limits and contextual validation. Host descriptor interpretation and resource rebinding remain host responsibilities; native decoding alone never authorizes dispatching saved external requests.

The full filesystem payload is self-contained. Reattaching a persistent filesystem requires the exact trusted namespace generation and contents. A newer filesystem must not silently replace the namespace belonging to saved execution. Internal publication flushes the requested filesystem generation and requires it to equal the durable generation before replacing `computers/<id>/execution`. Saving writes a temporary file, syncs its data, renames it over the prior publication and syncs the parent directory. Store close serializes with these operations. Interrupted temporary files never become visible publications; a later save replaces them. Reads bound the file size before allocating and reject symlinks and tombstoned computers. Discard syncs removal, allowing the eventual host lifecycle to consume a snapshot before issuing world actions.

A full-computer test closes and reopens the store, rebuilds execution against its recovered filesystem, and resumes the same instruction/accounting state. A separate producer/consumer subprocess test restores a live managed heap and queued terminal input in a fresh process, then finishes with the uninterrupted result and retirement count. A subprocess crash test covers every atomic write phase and successful retry over an abandoned temporary file. Ordinary CI additionally runs `tools/runtime-bundler/verify-revision-compatibility.py`: it builds the current revision, performs a real revision bump in an isolated fixture, builds the new revision and exchanges this full-computer checkpoint in both directions. Each subprocess checks its compiled package version before running. These are process interruption tests, not simulated power-loss durability evidence. Host settlement, consumption/reset policy, retained world-save generations and lifecycle wiring remain prerequisites for a supported durable contract.

Pending compilation retains the exact validated source bytes captured when the request was issued. Reconstruction uses that immutable input even if the filesystem source changed while compilation was pending; the original source/output revision guards still decide whether publication is stale.

`ComputerMachine::checkpoint` captures execution and opaque host descriptor bytes within `ComputerCheckpointLimits`. `restore_checkpoint` requires a `ComputerRestoreEnvironment` containing the expected computer ID, profile, process limits, freshly resolved capability schemas, filesystem and initial file capability. It returns a machine and host descriptors without executing Guest code. The caller must freeze and settle host actions before capture, validate/rebind restored descriptors, and durably consume the snapshot before advancing restored execution. Native admission does not enforce those host lifecycle obligations.

## Native transport (C ABI 21)

Five exports are appended to the existing transport: `compukter_checkpoint_save`, `compukter_checkpoint_restore`, `compukter_checkpoint_discard`, `compukter_checkpoint_host_size`, and `compukter_checkpoint_host_copy`. There are 49 exported functions. JNI uses Java 21 arrays; FFM uses caller-owned native buffers. Both check the exact ABI version before calls. No input pointer is retained.

Save accepts a session handle, store handle, fixed 16-byte computer ID and at most 4 MiB of opaque host descriptors. The session must belong to that store and ID. Restore accepts a store, a checked u32 boot flag (0: direct artifact entry with `/home` ownership, 1: ROM boot with root ownership), ID, trusted ROM bytes and current capability schemas. It returns the existing 9-byte creation wire with a fresh opaque session handle. A short output reports the required width before admission or handle publication. Restore does not execute Guest code or remove the durable snapshot.

Status 43 means no checkpoint, 44 incompatible context or format, 45 corrupt state/integrity, and 46 a checkpoint size/allocation limit. JNI/FFM map absence to a nullable restoration and the other three to typed checkpoint failures. Corruption never falls back to boot. Existing store/handle failures retain their existing codes. Host size/copy exposes the validated opaque descriptors for host rebinding; short copy reports the actual size without writing bytes. The descriptor cache is released after the first successful advance. The caller must bind descriptors and durably discard the publication before that advance, or explicitly discard on reset.

Computer filesystem admission flushes its last admitted generation before reading recovery state. Immediate reboot must not reopen an older on-disk namespace or replace pending generation bookkeeping with that older state. Native I/O stays on the persistence worker; admission waits for its barrier. This does not authorize concurrent writers for one computer identity.
